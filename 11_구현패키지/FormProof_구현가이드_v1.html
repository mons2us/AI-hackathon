03프레임워크 — 모듈과 데이터 흐름

원칙: 각 단계는 파일 → 파일 계약을 지키는 독립 명령이다. 그래서 단계 하나를 다른 구현(사내 LLM, FNO→GINO, 다른 CAD 커널)으로 바꿔도 나머지는 그대로 돈다.

04모듈별 설명

①조건 생성기 — 말을 계산할 수 있는 조건으로

  • 입력: 요청 문장 + 스케치에서 읽은 내용. 출력: spec/schema.json 형식의 설계 명세 → 판정 기준 spec/bike_mount_targets.json.
  • LLM 은 계산하지 않는다. 무엇을 계산할지 정하고, 수치는 근거 DB 에서만 골라 source 를 단다. 없으면 questions_to_user 로 묻는다.
  • 형식 검사에 실패하면 오류를 붙여 다시 요청(최대 3회). LLM 은 agent/llm.py 의 complete(system, user) 하나만 구현하면 바뀐다 (사내 OpenAI 호환 서버 · 수동 모드).

형상 생성기 ≠ 형상 AI

engine/gen_int.py형상 생성기
규칙 프로그램. 클램프 → 하우징 · 레일 · 걸이를 잇는 막대(두께 4–12 mm, 폭 4–16 mm) + 웹 0–3개 + 판 띠를 무작위 조합. 학습 데이터를 대량으로 만드는 용도. 미분 불가.
ai/deepsdf.py형상 AI (DeepSDF 방식)
형상마다 잠재 벡터 z(32차원) + 8층 MLP 디코더(좌표 → 점유 확률). 형상 공간을 연속으로 배워 미분으로 형상을 바꿀 수 있다.
중요. 생성기 형상 150개 중 최종 구조와 가장 비슷한 것의 IoU 는 0.14(중앙값 0.09). 생성기만 배우면 DeepSDF 가 우리 구조를 표현하지 못한다 → data/topopt_snapshots.npz(위상 최적화 기록 245개)를 반드시 함께 학습. 통과 기준: deepsdf fit 으로 최종 구조 복원 IoU ≥ 0.8.

②물리 AI — 형상 → 성능

모델입력 → 출력언제
CNN3D (해커톤과 같은 계열)점유 격자 → 스칼라 6개(f1 · f2 · 온도 · 터치 2 · 충격 응력). 무게는 정확식기준선. 해커톤 분리형에서 f1 평균 오차 6.9 %(≥ 50 Hz), 0.2초
FNO3D (추가)점유 + 좌표 → 스칼라 + 분포 2개(온도 상승, 충격 응력 log1p)권장. 같은 격자 데이터를 그대로 쓰고 분포까지 예측
GINO (다음 단계)불규칙 메쉬 · 점구름 → 분포STEP 입력 · 제품마다 설계 공간이 다를 때. 인터페이스 Surrogate.predict() 만 맞추면 교체

CNN 을 썼던 이유: 데이터가 이미 고정 격자, 목표가 스칼라(f1), 데이터 780개 · CPU 2코어, 형상 AI 출력(격자 점유)을 그대로 받아 미분을 돌려줘야 했음. GPU 에서는 FNO 를 기본으로 한다.

②잠재 공간 역설계 — ai/latent_search.py

무게(정확식) + 벌점 Σ max(0, 위반)² 을 z 에 대해 Adam 으로 최소화. 시작점 = 기준을 지키는 가장 가벼운 학습 형상들의 z. 결과 후보는 엔진 형식 파일로 저장 → 반드시 FEM 으로 재평가(검증 관문)하거나 START_RHO 로 위상 최적화의 시작 형상으로 쓴다. 해커톤 분리형에서 AI 후보(91 Hz 예측)가 재검증 86 Hz 로 미달한 적이 있다 — 물리 AI 예측만 믿지 않는다.

CADCAD 결합 — cad/

최적화 밀도(2 mm) → 0.5 mm 로 보간 · 가우시안 평활 · 등치면(marching cubes) → 고정 부품(CadQuery, parts.py) 합치기 → 채널 · 슬롯 · 핀/볼트 구멍 · 핸들바 구멍 빼기(manifold3d) → 수밀 STL. 맞닿는 면은 0.05 mm 어긋나게 잘라야 수밀이 깨지지 않는다. vox.py 는 출력 STL 을 단면 슬라이스로 다시 2 mm 격자화(검증 관문 입력).

07설계 결정과 이유

  • 조건 먼저, 형상은 계산으로: 사람은 형상을 그린 뒤 확인하지만, 여기서는 하중 · 기준에서 형상을 계산한다 → 처음부터 기준을 지키는 형상만 나온다.
  • LLM 은 계산하지 않는다: 범용 LLM 단독 3회 모두 불합격(스스로 1.3배라 예측한 흔들림이 실제 6.6배). 수치는 근거 DB · FEM 에서만.
  • 출력 형상을 다시 계산: 최적화 밀도와 출력 STL 은 다르다(평활 · 부품 결합 · 구멍). 출력할 형상으로 판정해야 한다.
  • 강체 폰 · 절반 모델: 폰 회전 관성이 진동수를 크게 바꾼다. 절반 모델은 대칭 모드만 보므로 비대칭 모드는 확인 필요 항목.
  • 2 mm 격자: CPU 에서 1회 반복 약 30초. 얇은 부재는 출력 형상 재검증(0.5 mm 표면 → 2 mm 재격자)으로 확인.
  • 물리 AI 인터페이스 고정: 형상 → (스칼라, 분포, 기울기). 모델은 바꿔 끼운다.

08실패 기록 — 같은 실수를 반복하지 않게

증상원인해결
진동수 178 Hz → 실제 98.5 Hz폰을 점질량으로 모델링크기 · 회전 관성 있는 강체로
1차 일체형이 폰을 잡지 못함고정 부품을 그림으로만 표시4면 고정(걸이 · 집게 · 잠금)을 고정 영역으로 넣고 재최적화. 충격 시 빠지는 힘 79 N > 마찰 11 N 확인
폰 온도 21 °C 를 못 맞춤위 레일이 판 위에서 폰 뒷면을 덮음레일을 판 아래(z′ 12–24)로
STL 수밀 깨짐잘라내는 면이 기존 면과 정확히 겹침자르는 형상을 0.05 mm 키움
메모리 부족으로 강제 종료FEM 계산 두 개 동시 실행(각 약 2 GB)무거운 계산은 한 번에 하나. 데이터 생성 병렬 수 = 메모리 / 2 GB
분포 그림이 엉뚱함배열 순서 (nx, ny, nz) 로 reshape항상 (nz, ny, nx)
AI 설계가 더 빨갛게 보임형상마다 따로 정규화한 모드 형상같은 척도의 물리량(흔들림 RMS · 응력 · 온도)으로
얇은 부재가 그림에서 사라짐평활 후 등치면 0.5 기준렌더링은 0.3 기준 · 연결성 확인
길 진동 근거 과대자갈길 최대값을 씀조약돌길 중앙값(34.6–45.6 Hz)
