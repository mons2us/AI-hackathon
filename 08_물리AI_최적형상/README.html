해커톤 시연 범위

① 요청 이해는 원래 LLM. 사내 해커톤에서 LLM API를 못 써서 07이 고정 시나리오 2개(거치대 3D 진동+정적, TV 2D 정적)로 대신. ②~⑥은 실제로 동작. LLM은 준비된 물리 모듈 선택·조건 설정까지만(코드 생성 안 함).

왜 "제품군마다 생성 + 재사용"인가

요청 1개만 보면 경로 A(약 20분)가 더 빠름 — 대리 모델은 데이터(FEM 수백 회) + 학습이 먼저 필요. 같은 제품군에 조건만 바뀐 요청이 반복될 때 이김 → 발표 핵심 수치 = 손익분기 요청 수(미측정, 시연에서 측정).

③ 데이터: 설계 범위 안 무작위 형상

DeepSDF는 최적화 결과가 아니라 설계 범위 안 다양한 무작위 형상으로 학습. 라벨만 쓰므로 제품 무관, 형상 생성에 FEM 불필요. ① 곧은 부재 ② 무작위 경유점 트러스 ③ 매끈한 덩어리(두 고정부에 붙은 조각만). PINO 정답은 형상마다 FEM 1회(약 7.5 s 추정), 최적점 근처는 능동 학습으로 보강.

④~⑤ 제품 무관 코드 + 품질 관문

2D/3D·물리 모듈·하중 수·출력 헤드를 spec.json에서 읽어 자동 구성 → 거치대·TV를 같은 코드로. 품질 관문 미달이면 경로 A로 자동 전환해 항상 답을 냄. 진동수 ① 레일리+보정 vs ② 직접 학습 비교 실험 포함.

G6개 형상 그룹 — 각각 무엇이고 어떤 형상이 나오나

형상 그룹 = 고정부의 위치·크기가 달라서 "도화지"(격자·고정부·설계 영역)가 바뀌는 경우. 그룹마다 DeepSDF가 1개씩(6개), PINO는 제품마다 1개(거치대·양발형·중앙형 3개). 폰 무게·각도, TV 무게·다리 간격처럼 도화지를 안 바꾸는 조건은 그룹이 아니라 모델 입력이나 공식으로 처리.

그림 읽는 법 — ① 문제 설정 (분홍 투명 = 설계 영역, 회색 = 고정부품, 보라 = 강체, 빨강 = 지지, 파랑 = 하중·질량 위치). ② 리허설에서 만든 무작위 형상 중 형식(A 직접 부재 · B 트러스 · C 삼각/사각 판 · D 열린 껍데기 · E 보강)별 대표와 실제 FEM 판정값. 합격 형상이 있으면 그중 가장 가벼운 것을 표시. 모든 그림은 절반 모델을 대칭면에 거울로 붙인 전체 모양. 질량은 고정부품 포함, TV 양발형은 다리 하나 기준.
형상 정리 (11-14 수정) — 처음 버전에는 ① 고정부 한 곳(클램프 링·발 패드)에만 붙어 힘을 전혀 안 받는 덩어리, ② 끝이 허공에 뜬 막대가 많았음 (거치대 형상의 약 70~90%에서 덩어리 발견, 재료의 4~8%). 고친 것: 고정부 두 곳 이상을 잇지 않는 덩어리 삭제 · 트러스 경유점 사슬의 끝이 고정부와 안 이어지면 버림 · 판에서 나온 막대는 판 위의 점에 연결 · 표면 한 번 다듬기. 놀고 있는 재료(하중을 걸었을 때 변형 에너지가 설계 재료 중앙값의 0.1% 미만인 칸) 비율로 측정: 거치대 7~8% → 0.5~2.5%, TV 중앙형 2.3% → 0%.
※ 골격(중심선) 기반 가지치기도 시험했으나 판·껍데기까지 깎아서(TV 판형 최대 79% 삭제) 버림.

수작업 CAD+FEM(전문가·시간), 상용 위상최적화(요청마다 처음부터), 생성형 3D(물리 검증 없음), LLM 단독(계산 오류) 대비 → 요청 → 명세 → 대리 모델 자동 생성·재사용 → 최적 설계 → FEM 검증 닫힌 루프. 개선 수치: 손익분기, 응답 시간, FEM 동등 무게, 같은 코드 3문제. 보강 필요: 상용 도구 비교 출처 ❓

③ DX 기여도

TV 스탠드 → VD, 갤럭시 거치대·액세서리 → MX, 가전 브라켓·프레임 → DA. 리드타임 단축, 경량화 재료비(무게 감소 × 생산량, 사내 수치 확인 ❓), 비전문가 초기 검증, 제품군별 대리 모델 = 기술 자산. 확장: 구조 → 진동 → 열 → 광학(기존 TV 백라이트 물리 AI 작업과 연결 가능).

원칙

확인되지 않은 효과 수치는 "추정" 또는 계산식으로만. 모든 설계 수치는 FEM 검증 값.

0설계 범위 — 받침·클램프는 고정, 팔만 최적화 (확정)

#왜 받침을 고정할 수밖에 없나
1사용 요구다 — 폰을 어디서 볼지(시야·손 위치)는 사용자가 정함. 07도 스케치·텍스트에서 받침 위치를 정함
2풀면 답이 뻔하다 — 무게 최소 + 진동수 기준이면 받침을 당길수록 유리 → 항상 "최대한 당겨라". 근거: 짧은 팔 T02 31.7 Hz vs 긴 팔 T03 10.4 Hz (07 1차 설계 표)
3미분이 안 된다 — 받침이 움직이면 고정·빈 곳·질량 절점이 2 mm 칸 단위로 불연속 변화 → 몇 개 값을 시도하는 바깥 루프로만 가능
4데이터가 위치 수만큼 는다 — DeepSDF·PINO 학습 데이터가 위치마다 필요 → 이틀에 3~5개가 한계
5받침판 각도는 필요도 낮다 — 07 템플릿에 각도 변수 없음(수평 4 mm 판). 폰 각도는 시판 홀더가 조절하고, 무게중심 이동은 하중 조건으로 반영

받침 위치 허용 범위는 확장 항목(07 수정 필요). 템플릿은 옆모습을 폭 20 mm로 압출한 2.5D, 최적화 결과는 폭 방향까지 바뀌는 3D.

0-1받침 위치 그룹 — 10종이 7개 위치로

08은 팔을 새로 설계하므로 문제를 정하는 것은 템플릿 ID가 아니라 받침 위치. 07의 스케치 매칭용 10종은 그대로 유지.

주황 = MVP 3개 위치(높이 16 mm, 앞 50·80·120). 큰 원 = 템플릿 2종이 같은 위치. 클램프 링은 모든 템플릿 기본값이 같음(핸들바 31.8 mm, 가정값).

0-2폰 기둥·폰 홀더와 폰 각도

폰 각도 = 하중 조건 (형상 불변)

각도가 바뀌면 무게중심 이동(22 mm × sin15° ≈ 6 mm) → problem.npz의 질량 절점 위치만 이동. DeepSDF 데이터는 그대로, PINO는 질량 마스크 채널로 처리. 최적화는 0°·±15° 제약을 동시에 만족.

⚠️ 레일리 몫은 항상 실제 이상(λ₁ ≤ R(u)) → 그대로 판정하면 위험해서 보정 비율을 학습. 고유값 문제 자체는 물리 손실로 학습하지 않음(모드 교차·부호·중복). 같이 학습 시: 손실은 상대오차로 크기 맞춤, 정답 없는 샘플은 마스크 손실(기존 run엔 진동수만 있음), 레일리 층으로 흐르는 기울기는 처음엔 stop-gradient. 먼저 기존 결과로 레일리 근사 오차를 확인(예: 10% 이내면 2단 구조 채택). 물리 손실의 데이터 절감 효과는 미검증.

7해커톤 2일 일정 (08)

8오해하기 쉬운 것

“91 Hz면 그 아래 진동엔 안 흔들린다” ✕

f₁보다 낮은 진동은 그대로·증폭 전달. T = 1/(1−r²): 80 Hz → 1.48배, 91.2 Hz → 1.33배, 61 Hz → 2.27배. 91 Hz 기준 = 흔들림을 키우지 않음.

FNO ≠ DeepSDF

FNO: 격자 → 격자 (밀도 → 변위, 물리). DeepSDF: (z, 점 좌표) → 거리 숫자 1개 (형상). 우리 입력은 이미 격자라 FNO에 바로 들어감.

FEM이 최종 심판

대리 모델 값은 예측. 판정은 항상 verify5.py 1 mm 재검증.

FEM 최적화도 미분 기반

adjoint + MMA. 차이는 1회 비용(FEM 약 7.5 s vs 신경망 ms).
