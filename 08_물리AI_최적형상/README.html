0설계 범위 — 받침·클램프는 고정, 팔만 최적화 (확정)

#왜 받침을 고정할 수밖에 없나
1사용 요구다 — 폰을 어디서 볼지(시야·손 위치)는 사용자가 정함. 07도 스케치·텍스트에서 받침 위치를 정함
2풀면 답이 뻔하다 — 무게 최소 + 진동수 기준이면 받침을 당길수록 유리 → 항상 "최대한 당겨라". 근거: 짧은 팔 T02 31.7 Hz vs 긴 팔 T03 10.4 Hz (07 1차 설계 표)
3미분이 안 된다 — 받침이 움직이면 고정·빈 곳·질량 절점이 2 mm 칸 단위로 불연속 변화 → 몇 개 값을 시도하는 바깥 루프로만 가능
4데이터가 위치 수만큼 는다 — DeepSDF·PINO 학습 데이터가 위치마다 필요 → 이틀에 3~5개가 한계
5각도는 표현 수단이 없다 — 07 템플릿에 각도 변수 없음(수평 4 mm 판). 2 mm 격자에서 기울인 판은 칸 2개짜리 계단 → 끊김 위험

받침 위치 허용 범위·각도 변수는 확장 항목(07 수정 필요). 템플릿은 옆모습을 폭 20 mm로 압출한 2.5D, 최적화 결과는 폭 방향까지 바뀌는 3D.

2두 가지 경로 — A는 검증 완료, B가 해커톤 목표

3대리 모델 설계안 — PINO (3D FNO + 물리 손실)

⚠️ 진동수를 "모드 예측 + 레일리 몫"으로 계산하면 실제보다 높게 나와(λ₁ ≤ R(φ)) 91 Hz 판정을 잘못 통과시킬 수 있음 → 사용하지 않음. 물리 손실의 데이터 절감 효과는 미검증이며 학습 시간은 오히려 늘 수 있음.

학습 데이터: opt3d.py 반복마다 푸는 FEM 결과(ρ, u, f, 응력)를 저장 → 추가 계산 없음. 폰 기종·템플릿·기준을 바꿔 병렬 실행. 한 최적화 안 샘플은 서로 비슷하므로 범위 밖 형상은 FEM 확인 필수.

3+라벨 마스크 — 거르기가 아니라 칸 단위 덮어쓰기

모든 z의 형상이 PINO로 감(버리지 않음). 마스크는 범위만 보장하고 연결성은 보장하지 않음 → 끊긴 형상도 학습 데이터에 넣어 PINO가 "낮은 진동수"로 평가하게 하고, 최종안은 FEM으로 확인. 마스크를 빼면 링·받침이 칸 단위로 어긋나거나, 최적화가 링을 얇게 만드는 z로 빠져 대리 모델이 틀린 점수를 줄 위험.
학습 데이터출처비용
DeepSDF 형상 (수백 개)07 템플릿 파라미터 무작위 변형 + opt3d 스냅샷 + 최적화 결과(39.8 g 등)거의 0 / 기존 run 재사용
PINO 정답형상마다 FEM 1회 (모드 S·A + 정적 충격)약 7.5 s/개 추정 → 500개 ≈ 1시간 (미측정)

최적화 결과를 꼭 섞을 것: 템플릿 변형만 배우면 z 공간에 "템플릿처럼 생긴 형상"만 들어가 경로 A(39.8 g)보다 무거운 답이 나올 가능성이 큼. 받침 위치가 다른 템플릿은 한 모델에 섞지 않음(받침이 흐릿하게 두 군데 생김).

7해커톤 2일 일정 (08)

8오해하기 쉬운 것

“91 Hz면 그 아래 진동엔 안 흔들린다” ✕

f₁보다 낮은 진동은 그대로·증폭 전달. T = 1/(1−r²): 80 Hz → 1.48배, 91.2 Hz → 1.33배, 61 Hz → 2.27배. 91 Hz 기준 = 흔들림을 키우지 않음.

FNO ≠ DeepSDF

FNO: 격자 → 격자 (밀도 → 변위, 물리). DeepSDF: (z, 점 좌표) → 거리 숫자 1개 (형상). 우리 입력은 이미 격자라 FNO에 바로 들어감.

FEM이 최종 심판

대리 모델 값은 예측. 판정은 항상 verify5.py 1 mm 재검증.

FEM 최적화도 미분 기반

adjoint + MMA. 차이는 1회 비용(FEM 약 7.5 s vs 신경망 ms).
