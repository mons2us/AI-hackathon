0아주 쉽게 — 마을 전화망

집 = 노드

FEM 절점. 집마다 메모지(숫자)가 하나 있음.

전화선 = 엣지

메시에서 선으로 이어진 절점 쌍. 전화선에도 메모지가 있음.

한 라운드

① 전화선마다 양쪽 집 얘기를 듣고 통화 메모를 새로 씀 → ② 집마다 연결된 통화 메모를 다 더해 자기 메모를 고침.

15라운드 후

각 집이 자기 메모를 보고 답(변위·속도)을 발표.

GNOMeshGraphNets
누구에게 묻나반지름 r 원 안의 모든 점메시에서 선으로 직접 이어진 점만
선(엣지)의 역할가중치 숫자를 한 번 내고 끝자기 메모지를 갖고 라운드마다 새로 씀

한 줄 요약: MeshGraphNets = 메시 선을 따라 이웃끼리 메모를 주고받는 일을 15번 반복. 그래서 정보는 15칸까지만 감 — 동적 문제(한 걸음이 짧은 시간)에는 충분하지만, 하중이 반대편 고정점까지 전달돼야 하는 우리 정적 문제에는 부족(9절).

1한 줄 요약

FEM 메시의 절점 = 노드, 요소 변 = 엣지로 보고, 이웃끼리 정보를 주고받는 일(메시지 전달)을 15번 반복해 각 절점의 다음 상태(속도·가속도 등)를 예측하는 GNN. DeepMind, ICLR 2021 [1].

입력 형식 ＼ 보는 범위이웃만 (국소)전체 (전역)
정형 격자CNNFNO
아무 점 (메시·점구름)GNO · MeshGraphNetsGINO · Transolver

GNO와 같은 칸(메시 + 국소). 차이는 8절. NVIDIA PhysicsNeMo 예제 목록에도 "MeshGraphNet for transient vortex shedding", "MeshGraphNet with Lagrangian mesh" 등이 있음 [3].

2입력 — 노드 특징과 엣지 특징 논문

무엇담는 정보비고
노드 vi노드 종류(one-hot: 일반·고정·유입 경계 등) + 동적 값(위치·속도·운동량 등)판 변형 문제(DeformingPlate)는 노드 종류만 입력
메시 엣지 eMij메시 공간 상대 위치 uij = ui − uj 와 길이 |uij| (+ 변형체는 월드 공간 xij, |xij|)절대 위치가 아니라 상대 위치 → 평행이동 불변 (GNO의 Δx와 같은 발상)
월드 엣지 eWijxij, |xij|. 메시 엣지가 없는 쌍 중 |xi − xj| < rW 이면 추가rW = 0.03 (판), 0.05 (천). 빼면 오차 51~92% 증가 [1]

모든 입력·정답은 데이터셋 통계로 평균 0, 분산 1 정규화 [1].

3구조 — 인코딩 → 처리 × 15 → 디코딩 논문

4처리 블록 하나 = "엣지 먼저, 그다음 노드" 논문

① e′ij = eij + fM( eij, vi, vj )
② v′i = vi + fV( vi, Σj e′ij )

① 엣지 갱신

엣지마다 "내 값 + 양 끝 노드 값"을 MLP에 넣어 엣지 값을 새로 씀. 엣지가 자기 상태를 가지고 다음 블록으로 넘김(GNO에는 없는 부분).

② 노드 갱신

노드로 들어오는 엣지 값들을 합(Σ)해서, 내 값과 함께 MLP에 넣어 노드 값을 새로 씀. 월드 엣지가 있으면 그 합도 따로 넣음.

잔차 연결

"새 값 = 옛 값 + 바뀐 양". 15블록을 깊게 쌓아도 학습이 안정되도록 하는 장치.

한 블록에서 정보가 가는 거리 = 엣지 1개. 15블록이면 각 노드는 엣지 15개 거리까지 정보를 받음 → 9절에서 이게 우리 문제의 핵심 제약이 됨.

예시에서 볼 것 — ① 노드 2·3이 같은 결과(2.092)인 것은 우연: 둘 다 이웃 값이 1.5·0.5·2.5이고 엣지 길이 조합(2, 2.236)이 엇갈려 있어, 예시의 직선식에서는 합이 같아짐. 실제 MLP(비선형)에서는 일반적으로 다름. ② 하중 노드 4의 정보(v=2.5)는 엣지로 이어진 2·3에만 1블록 만에 전달, 고정 노드 1에는 아직 안 닿음(1의 이웃은 2·3) → 블록을 하나 더 쌓아야 1이 4의 하중을 "앎". ③ 고정 노드 1의 출력은 노드 종류로 구분해 경계조건으로 덮어씀 예시의 단순화. ④ 학습 = 출력과 정답(다음 시점 상태 또는 FEM 해)의 차이를 줄이도록 빨간 숫자를 수정.

숫자는 이해용으로 정한 값이며 학습된 가중치가 아님. 표 값은 Python으로 계산해 버튼 결과와 대조함. 실제 MLP는 직선식이 아니라 ReLU 은닉층 2개.

6출력·시간 진행 — "변화율"을 예측해 한 걸음씩 논문

문제디코더가 내는 것다음 상태 계산
천(cloth)가속도 ẍ2차 적분: qt+1 = p + 2qt − qt−1
초탄성 판(DeformingPlate)속도 ẋ + 보조 출력 von Mises 응력1차 적분: qt+1 = p + qt
유동(CylinderFlow, Airfoil)운동량 변화 + 압력1차 적분
오차 누적 대책 — 잡음 주입: 학습 때 입력에 일부러 작은 가우스 잡음(위치 1e-3~3e-3 등)을 넣어, "조금 틀린 입력에서도 제자리로 돌아오는" 법을 배우게 함 [1]. 그래도 천 시뮬레이션은 약 50걸음 뒤 정답과 어긋나기 시작(혼돈 거동)이라고 저자들이 보고.

8GNO와 무엇이 다른가

GNOMeshGraphNets
엣지 만드는 법반지름 r 안의 점 전부메시 연결(요소 변) + 필요시 월드 엣지(rW)
엣지의 역할κ(Δ, a)로 가중치 숫자를 계산하고 끝자기 상태(128차원)를 갖고 블록마다 갱신·전달
모으는 방식가중 평균 (적분의 근사)합(Σ) 후 MLP
층(블록)보통 수 층15블록, 블록마다 다른 가중치
해상도 변경설계 목표(이산화 불변, 신경 연산자)메시 연결에 의존 — 원 논문은 적응 리메싱으로 대응, "신경 연산자" 이론 틀 밖
주 용도정적·파라메트릭 PDE의 해 연산자시간 진행(동적) 시뮬레이션 + 정적도 가능
한 줄로: GNO = "적분을 그래프로 근사"(수학에서 출발), MeshGraphNets = "FEM 메시 위에서 메시지 전달"(GNN에서 출발). 계산 모양은 비슷하지만 엣지가 상태를 가지느냐, 무엇을 이웃으로 보느냐가 다름.

9우리 문제(거치대·TV 스탠드)에 쓴다면

그래프 만들기는 쉬움

우리 FEM은 2 mm hex8 복셀 → 절점 = 노드, 요소 변 = 엣지로 바로 그래프가 됨(거치대 약 2.4만 칸). 재료 칸만 남기면 형상마다 그래프 모양이 달라지는 것도 자연스럽게 표현됨.

핵심 제약 — 정보가 닿는 거리

닿는 거리 ≈ 블록 수 × 엣지 길이 = 15 × 2 mm = 30 mm
필요한 거리15블록이면
거치대 bike_pad80 (받침 ↔ 클램프)설계 영역 길이 124 mm부족 (약 1/4)
TV 중앙형 (5 mm 칸)400 mm15 × 5 = 75 mm → 부족

계산은 단순 산수이며, 실제로는 대각 엣지·형상에 따라 다름 추정. 정적 탄성은 하중점의 힘이 지지점까지 한 번에 전달돼야 답이 정해지는 전역 문제. 동적 문제는 한 걸음(짧은 시간)에 정보가 멀리 갈 필요가 없어 15블록으로 충분했던 것.

대응 방법대가
블록 수를 60개 이상으로계산·메모리 증가, 깊은 GNN의 학습 불안정
다중 해상도 그래프(거친 그래프에서 멀리, 고운 그래프에서 세부)구현 복잡 — 후속 연구들이 있으나 이번에 세부를 확인하지 않음 확인 필요
GINO처럼 가운데를 FNO로결국 격자가 필요 → 우리 데이터는 이미 격자라 FNO 직접이 더 단순
결론: 해커톤에서는 FNO 기반 PINO 유지가 맞음 — 데이터가 정형 격자이고, 정적 탄성의 전역 전달을 FNO가 한 층에서 처리. MeshGraphNets는 ① STEP·곡면 메시 입력, ② 진동 응답의 시간 이력(과도 응답) 예측처럼 메시 + 동적 문제가 될 때 후보. PhysicsNeMo에 구현이 있어 시작 비용은 낮음 [3].
오해 ✕ "FEM 메시를 그대로 쓰니 FEM과 같은 정확도" — 아님. 메시는 입력 형식일 뿐이고, 계산은 학습된 MLP의 근사. 판 문제 한 걸음 오차는 작지만(0.25×10⁻³) 전체 진행 오차는 15.1×10⁻³로 커짐 [1]. 최종 판정은 여전히 FEM.
